The Field

A surface is not a document. You clear it and redraw it, every frame, forever — and nothing you drew last time is still there.

Lesson one, carried by ….

The one idea and it is the one people fight hardest

An HTML page is a document: you put an element in it and it stays there, the browser remembers it, and it is still there next second because something is keeping it. A canvas is nothing like that. A canvas is a rectangle of pixels. You draw on it and the drawing is not an object, it is paint. There is no list of what you drew, nothing to update, and nothing that will redraw it for you.

Everything that follows in game programming falls out of that. You keep the state; the screen keeps nothing.

Clear it and nothing brings it back. Resize the window and it goes too, because the browser reallocates the pixel buffer and everything painted on it is gone. There is no bug here; this is the contract.

Two pixels, not one the thing every first canvas gets wrong

A canvas has two sizes and they are not the same size. style.width is how big it looks. canvas.width is how many pixels it actually has. Set only the first and the browser stretches a small buffer over a large area, which is why so many first canvases look soft.

const canvas = document.getElementById('c');
const ctx = canvas.getContext('2d');

function fit() {
  const dpr = window.devicePixelRatio || 1;
  const rect = canvas.getBoundingClientRect();
  canvas.width  = Math.round(rect.width  * dpr);   // real pixels
  canvas.height = Math.round(rect.height * dpr);
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);          // draw in CSS pixels
  return rect;                                      // the size you think in
}

Draw in CSS pixels, store in device pixels. The scale() line means every coordinate you write afterwards is in the units you were thinking in, and the buffer underneath is as sharp as the display can manage. Get this wrong on day one and every measurement you make for the rest of the project is off by the same factor.

Drawing a light a dot is not a light

A firefly is not a filled circle. It is a small bright core inside a wide soft falloff, and the falloff is what your eye reads as glow. A radial gradient does it in four lines and costs nothing.

function lantern(ctx, x, y, radius, brightness) {
  const g = ctx.createRadialGradient(x, y, 0, x, y, radius);
  g.addColorStop(0.00, `rgba(255,236,180,${brightness})`);
  g.addColorStop(0.35, `rgba(240,198,106,${brightness * 0.45})`);
  g.addColorStop(1.00, 'rgba(240,198,106,0)');
  ctx.fillStyle = g;
  ctx.beginPath();
  ctx.arc(x, y, radius, 0, Math.PI * 2);
  ctx.fill();
}

Exercise

Draw the four lanterns in a ring rather than a row, and make the ring's radius depend on the canvas size so it survives a resize. Then draw them at four different brightnesses and notice that you have just invented the state the next lesson is going to animate — you had to keep those four numbers somewhere, and the canvas would not keep them for you.

Done when: you can resize the window, watch the drawing vanish, and say without thinking why it vanished and whose job it is to put it back.
