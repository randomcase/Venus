The Clock

Simulated time and wall time are different quantities. A game that confuses them runs at a different speed on every machine it will ever be played on.

Lesson two, carried by ….

The loop and the mistake inside it

Every game is the same loop: work out how much time has passed, advance the world by that much, draw it, wait for the next frame. The mistake is in the second step, and it is always the same mistake — advancing the world by one step instead of by the time that passed.

// wrong, and it will look fine on your machine
function frame() {
  phase += 0.01;
  draw();
  requestAnimationFrame(frame);
}

// right
let last = performance.now();
function frame(now) {
  const dt = now - last;   // milliseconds actually elapsed
  last = now;
  update(dt);              // advance the world BY THAT MUCH
  draw();
  requestAnimationFrame(frame);
}

The first version is not slower or faster. It is unpredictable. It runs at 60 steps a second on one machine, 144 on another, and 4 on a laptop with a dying battery in a background tab. Nothing about it is wrong until somebody else runs it, which is the worst kind of wrong.

A firefly is a phase one number, from 0 to 1

Give the firefly a period — how long one cycle takes — and a phase, which is how far through the cycle it is. Advance the phase by dt / period. When it reaches 1 it flashes and goes back to 0. That is a complete firefly, and it is four lines.

function update(dt) {
  phase += dt / periodMillis;
  if (phase >= 1) { phase -= 1; flashes++; }   // wrap, do not clamp
}

// brightness: dark most of the cycle, then a fast spike near the end
const brightness = Math.pow(phase, 8);

Tick ignore dt and the light is driven by frames instead of time. Then switch to another tab for a few seconds and come back. With dt the firefly has kept its own time and is where it should be; without it, it has simply stopped and lost exactly as long as you were gone.

The clamp the one line nobody explains

const dt = Math.min(now - last, 100);   // never advance more than 100ms at once

Come back to a backgrounded tab and dt is not 16 milliseconds, it is forty thousand. Without the clamp the world advances forty seconds in one frame: things teleport through walls, every timer fires at once, and physics explodes. The clamp says the simulation may fall behind real time, which is a choice, and it is a better choice than the alternative.

Exercise

Give the firefly a fixed timestep: accumulate dt and run the update in whole 16 ms slices, keeping the remainder for next frame. Then set the period to 300 ms and compare it against the variable-step version on the same machine. This is the difference between a simulation that is reproducible from a seed and one that is not, and lesson four cannot exist without it.

Done when: you can say what your game does when the tab is hidden for five minutes, and it is what you intended rather than what happened.
