The Swarm

Update and draw are different jobs. Four lights, one rule between them, and no one in charge — which turns out to be enough.

Lesson three, carried by ….

Split the loop before you have anything worth splitting

Update changes the world. Draw looks at the world and paints it. They must not be the same function, and draw must not change anything — not a counter, not a flag, not a "just this once".

The reason is not tidiness. A browser skips draws: hidden tab, low battery, a frame that ran long. If drawing advances your state then your world runs at a speed that depends on whether anyone is looking at it, and the bug only appears on someone else's machine, intermittently, months later.

function frame(now) {
  const dt = Math.min(now - last, 100); last = now;
  update(dt);      // may change everything
  draw();          // may change NOTHING
  requestAnimationFrame(frame);
}

The rule between them three lines, and it is the whole lesson

When a firefly flashes, every firefly that can see it moves its own clock forward by a fraction of how far along it already was.

function nudge(f, epsilon) {
  f.phase = Math.min(1, f.phase * (1 + epsilon));
  return f.phase >= 1;      // true: this one flashes too, in the same round
}

The asymmetry is everything. A firefly that has nearly finished its cycle is dragged a long way; one that just flashed is barely moved. Move everybody by the same amount instead and the swarm sloshes around a mean and never settles. This one line is the difference between a crowd and a rhythm.

click a light to knock it out of step

Set coupling to zero and they never agree — that is the control, and without it the rest is a light show rather than a result. Scatter them and watch the coherence climb. Then knock one out and watch the others pull it back in without deciding to.

Measuring it a light show is not a result

"They look synchronised" is not a measurement. Treat each phase as an angle, put a unit vector at that angle, average the vectors, and take the length of the average. One means every light is at the same phase; zero means they are spread evenly round the cycle.

function coherence(swarm) {
  let x = 0, y = 0;
  for (const f of swarm) {
    x += Math.cos(2 * Math.PI * f.phase);
    y += Math.sin(2 * Math.PI * f.phase);
  }
  return Math.hypot(x / swarm.length, y / swarm.length);   // 0 .. 1
}

What r does not tell you. Zero does not mean random. Two tight clusters exactly opposite each other also average to zero, and on a sparse graph that is a real state a swarm can fall into and stay in — still flashing, still cascading, permanently not agreeing. Every liveness signal looks healthy. This is why the demo draws the ring of phases as well as printing r.

Exercise

Give each firefly a target offset — 0, ¼, ½, ¾ — and couple them towards their offset from the flasher instead of towards the flash. They will lock into a procession: in step, in order, still apart. Then measure it with the same r, subtracting each firefly's offset before you take the angle. Same swarm, same rule, one changed target, and the thing it converges to is completely different.

Done when: you have a control in your demo — a setting where the thing you are claiming does not happen — and you check it as often as you check the success case.
