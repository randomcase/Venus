Whoever owns the state owns the game. This is the lesson where the light leaves your machine, and it is the only one that needs a server.

Lesson four, carried by ….

The problem you cannot see alone until there are two of you

Lesson three runs entirely in your tab. It is correct, it is reproducible, and it is single-player — and the moment a second person opens it, they get a different swarm. Two browsers, two sets of random phases, two versions of the truth, and nothing to reconcile them.

The fix is not to send more messages. It is to decide, once, who is holding the state. Everyone else renders what they are told.

The server owns it Java, and about forty lines that matter

public final class Swarm {

    private final ReentrantLock lock = new ReentrantLock();
    private final Map<Long, Firefly> fireflies = new LinkedHashMap<>();
    private final Map<Long, Set<Long>> neighbours = new HashMap<>();

    public RoundResult round(long stepMillis, double coupling, int maxCascadeDepth) {
        Set<Long> fired = new LinkedHashSet<>();
        List<Firefly> frontier = new ArrayList<>();

        for (Firefly f : fireflies.values()) {
            if (f.advance(stepMillis) && fired.add(f.id())) frontier.add(f);
        }
        int spontaneous = fired.size();

        int depth = 0;
        while (!frontier.isEmpty() && depth < maxCascadeDepth) {
            List<Firefly> next = new ArrayList<>();
            for (Firefly flasher : frontier) {
                flasher.flash();
                for (Long id : neighbours.get(flasher.id())) {
                    if (fired.contains(id)) continue;          // refractory
                    Firefly n = fireflies.get(id);
                    if (n.nudge(coupling) && fired.add(id)) next.add(n);
                }
            }
            frontier = next; depth++;
        }
        for (Firefly stranded : frontier) stranded.flash();

        return new RoundResult(List.copyOf(fired), spontaneous, depth);
    }
}

This is real and it runs — it is the swarm module of the lightning-bug service, with the comments stripped. Note what is not in it: no rendering, no colours, no canvas, no notion of a screen. The server holds phases and topology. What a firefly looks like is not its business, and the day you put a colour in here is the day the server starts having opinions it cannot defend.

The browser stops deciding and starts asking

let world = { fireflies: [], coherence: { r: 0 } };
let lastGoodReply = 0;

async function poll() {
  const res = await fetch('http://localhost:8080/api/swarm');
  world = await res.json();          // the server's answer replaces mine
  lastGoodReply = performance.now();
}
setInterval(poll, 100);              // truth at 10 Hz

function frame() {                   // drawing at 60 Hz, from whatever I last heard
  draw(world);
  requestAnimationFrame(frame);
}

Draw still runs at 60 frames a second; only the truth arrives at whatever rate the network manages. Between updates you interpolate, which is a polite word for guessing — and the guess is always overwritten by the next real answer, which is the rule that keeps clients from drifting apart.

The connect button expects lightning-bug running on port 8080. If it is not there the demo says so and keeps running its own local swarm — it does not pretend, and it does not silently fall back without telling you. A demo that hides a failed connection has taught you the opposite of this lesson.

What this costs you and it is worth saying before you choose it

Latency becomes visible. The swarm is now as far away as the network is slow, and every input has a round trip in it.

You have a new failure mode: disagreement. Not a crash — a client showing something the server does not believe. It looks fine. Nobody reports it.

Reproducibility moves. The seed is on the server now, which is exactly why the service echoes it back on every reply. A simulation whose initial conditions cannot be repeated cannot be debugged, and moving it to a server does not change that — it just changes who has to hand you the number.

Exercise

Open the demo in two windows with the server running. Confirm they show the same swarm. Then stop the server and watch both windows carry on drawing the last thing they were told, indefinitely, perfectly smoothly, and completely wrong. Add whatever it takes for a window to notice and say so — a timestamp on the last good reply is enough. That is the whole of network programming that anybody actually needs on the first day.

Done when: your client can tell the difference between "the world is still" and "I have stopped hearing about the world", and it says which one out loud.

Where the line goes next

Four lanterns, and then whoever is holding the file. The coupling rule only ever moves the clock of something close enough to see the flash — that is why this lesson is last, and why it is the one where the light leaves the machine it was lit on.
