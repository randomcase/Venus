The Persistence Layer

State that survives the tab closing, with no script and no server. There is not a single input on this page: every control is a link, the URL is the whole document, and the Back button is undo. no script †

The layer four lines, and they are all of it

a link writes it       <a href="#st-b2">
the browser keeps it   in the URL, in history, in the bookmark
:target reads it        #st-b2:target
:has() acts on it       .board:has(#st-b2:target) { ... }

Reload this page after picking a state below. It comes back. Bookmark it and the bookmark is a save file. Send the URL to somebody and they open your state, not the defaults. Press Back and you undo. None of that is a trick and none of it is script; it is what a browser has always done with the part of the address after the hash, and :target is the selector that has always been able to see it.

Three berths by two watches is six links, not five controls. A document has one :target at a time, so the stored value has to name the whole combination — there is no way to change the watch and leave the berth alone, because there is only one thing in the store. Add a fourth berth and you write two more anchors and two more links. That is the same bargain as compound :has(): no multiplication in the language, so you write the products out, and every cell was typed by someone who can be asked about it.

These are CSS counters, incremented on an element inside the store strip at the top of the document — which is why the strip is first in the DOM and why it will stay there. The one rule you cannot break has not changed: a counter prints after the things that increment it. What has changed is that the thing incrementing it is now durable. Reload and the numbers are still here.

Cold · no state stored

There is no fragment in the address, so there is no :target anywhere in this document, and the board is showing you its defaults. This is the case everybody forgets to design. It is selected for explicitly — .board:not(:has(:target)) — because a persistence layer that has nothing sensible to say on a cold start is not finished. What it will not do and where the lying usually starts

The query string is write-only

<form method="get"> is still how a board hands its state to the next page, and it still works. But nothing in CSS can read ?berth=b back — not on the receiving page, not on this one, not anywhere. The query half of a URL is for humans, servers and logs. The fragment is the only half this yard can read, and a layer that claimed otherwise would be lying about where the state actually lives.

One target, whole states only

There is no partial update. Every link names the entire state because the state is one id, so the control surface is a grid of combinations rather than a row of switches. If that grid gets too big to type, the honest response is fewer axes — not a smaller grid with the missing cells quietly unreachable.

Two more things worth knowing. Following a link scrolls to the target, so the anchors here are offset off-screen above the content and are one pixel wide; that is cosmetic and it is the only cosmetic hack on the page. And the fragment is never sent to a server — it lives entirely in the browser, which is a privacy property worth having and worth saying out loud: this page has no idea what state you are in and could not tell anyone if it wanted to.

Carry it on §5 and §6

This is the one thing on the page that does not persist, and it is here so the difference is visible: the button posts to another file and the state goes with it in the query string, where the receiving page cannot read it. The fragment stays behind. Two halves of one address, one of which this yard can see.

Where to start

Pick a state, reload, and then press Back twice. Then copy the address and open it in another window. Then remove everything from the # onward and watch the cold-start panel come back. Four experiments, no script, and at the end of them you know exactly where the state was the whole time.
